# Proposed implementation acceptance plan

These are requirements for a separately authorized implementation, not additions to permanent tests in this phase. The current diagnostic measures the **existing defect**; a corrected implementation should intentionally invalidate its expectation of three admitted decodes. Preserve its immutable evidence and add real acceptance assertions to the existing test suites when implementation is authorized.

## Review gates and implementation stages

1. Human policy review: choose encoded and estimated-PCM budgets, unknown metadata handling, supported metadata provider/format scope (or explicitly approved estimation risk), waiting/abandonment deadline and user-visible reasons. Confirm CONFIG ownership, single active pipeline/latest pending behavior and waveform-independent playback. No version/schema/source changes before this approval.
2. Authorized implementation: put approved policy in CONFIG through existing deep-freeze hierarchy; keep Scrubber as sole optional-job owner; preserve UI Queue/request guard and existing source/recorder interfaces. Add pre-read admission and one whole-pipeline slot, one pending intent, release only after underlying settlement, and cleanup for metadata/deadline listeners. Any bounded metadata provider must have its own approved limits/layout contract. No incremental waveform implementation, worker or global mutable governor.
3. Behavioral validation: add permanent concurrency/admission/freshness/cleanup cases and validate negative controls in disposable source copies. Preserve multichannel and final-bucket tests and drag contracts. Run focused source/queue/recording/preset/UI tests, then the full suite, build and distribution validation.
4. Native integration: small native WAV plus optional compressed fixtures supported by the approved policy; playback during optional refusal; ordinary portable/root/nested operation; F/G/H regression diagnostics including recorder natural EOF/finalization. Record environment, actual policy, small input sizes, artifact hashes, errors and unhandled rejections. Review implementation separately; do not merge/release automatically.

No OOM test is required or permitted. Exact fixture counters, bounded allocations and resource ownership are meaningful. A clean console is insufficient proof of resource admission.

## Native permanent integration requirements

- Native Chromium with a generated 4-second stereo WAV: production Queue→UI→manager→media pipeline, advancing currentTime, ready waveform, accurate status and seek. If the approved metadata profile supports compressed audio, include a small real supported compressed file too; do not label WAV as compressed-codec coverage.
- A valid native File above approved waveform budget plays/pauses/seeks/auto-advances and can be recorded. Assert no File.arrayBuffer or waveform decode invocation and the unavailable resource-policy reason. Use a small File and test-only approved-policy injection/config fixture so the integration need not create a large file. Clearly distinguish native playback from policy injection.
- A valid native File with controlled optional read/decode refusal continues playback and recording; next valid eligible File recovers. Native malformed/unsupported media follows independent existing source-error semantics, including no stale cleanup of the winner.
- Native known multichannel/high-sample-rate short input validates actual output channels/rate and approved metadata policy. Keep full-channel peaks; do not mistake `(1,1,44100)` for a channel/duration bound.
- File→fake-device Mic and controlled Stream refusal; real native MediaStream synthetic stereo support where established diagnostics cover it. Record fake permissions/device limitations; do not claim physical mic/share-dialog acceptance.
- Pending Queue activation removal/Clear/replacement/duplicate File identity and EOF remain governed by F's existing request/entry/media guards. Playback URL revocation remains AudioEngine-owned; waveform code must not call release/unload.
- Native MediaRecorder across normal track changes, held finalization plus natural EOF, one successor activation, lock/unlock and downloadable prior export after later recorder failure. Waveform refusal/settlement must not start/stop/finalize capture or stop upstream tracks.
- Portable single-file HTML with no external runtime requests, hosted root and nested paths, same version/schema; verify generated outputs in disposable build locations. Schema-10 migration/round-trip tests remain green. Canonical releases and previous audit evidence remain byte-identical.

## Diagnostics and interpretation

Proposed scalar diagnostic snapshot: active stage/current-vs-obsolete generation, actual outstanding read/native count, pending count (0/1), read/context/decode initiation counts, admitted/declined/stale/settled/failed totals, File.size without name/content by default, metadata source/credibility, estimate and actual output dimensions/bytes, context output rate, reason and elapsed waiting/decode time, approved policy snapshot. Keep at most current/last detail records; no stored File, AudioBuffer, channel views, ArrayBuffer or promise history.

Native API operation counts do not reveal physical decoder thread scheduling. Exact read byteLength and returned AudioBuffer dimensions are measured JavaScript-visible facts. Device/process RSS or browser memory traces, if later collected, must be labelled separately with sampling method and platform; they cannot validate a universal memory cap. Estimates use declared/observed duration/rate/channels and must disclose metadata uncertainty/native scratch. A detached buffer is not evidence of freed native encoded storage. Garbage collection is nondeterministic; logical reference removal and native settlement are assertions, immediate resident-memory drops are not.

## Definition of Done for the future correction

Approved CONFIG policy and explicit format/unknown-metadata contract; one active pipeline and one newest pending intent; no extra work during unresolved operations; honest deadline/refusal presentation; no stale commit; recovered gate after real read/native rejection/settlement; correct all-channel/final-bucket peaks; seek/play/record independent of waveform; F/H lifecycle and H.1 mutation contracts preserved; no duplicated listeners or unbounded diagnostic/caching records; all permanent and native regressions pass; portable/root/nested/schema-10 compatibility verified; native limitations and device calibration reviewed; implementation PR independently accepted. AUD-007 closure requires that authorized implementation and review, not this policy package.
